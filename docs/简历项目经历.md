## 版本 A：AI / AI Agent / 大模型应用岗（推荐）

**基于 DeepSeek 大模型的 AI 电商智能客服 Agent** ｜ 个人项目 ｜ 2026.09 – 2026.11

- 设计并实现基于 DeepSeek `deepseek-chat` 的智能客服 Agent，采用原生 Function Calling 自建工作循环（意图识别 → 工具选择 → 执行 → 基于结果生成回答），支持自然语言咨询与连续追问，替代关键词匹配原型。
- 设计 12 个结构化工具（商品/库存/FAQ/推荐/转人工/订单/物流/退款/售后/下单/状态流转/知识检索），统一 JSON Schema 声明与异常兜底，约束模型只能基于真实查询结果作答，抑制价格与库存幻觉。
- 实现轻量 RAG：知识文档切分（16 块）、中文 bi-gram 分词、TF-IDF 向量化与余弦相似度 Top-K 检索；用标准问答集标定拒答阈值（0.28），无可靠结果时强制拒答；引入父文档扩展补充同商品切片，并为 FAQ 增加「精确关键词 + 语义检索」混合检索兜底。
- 实现有状态模拟业务：下单真实校验并扣减库存、生成订单、售后申请状态机流转、运行时状态持久化到 JSON；结构化实时字段（库存/订单）与静态文本检索职责分离。
- 实现多轮对话记忆：按用户隔离、上下文长度控制、超长时由大模型生成滚动摘要作为长期记忆；强制价格/库存每次重新查工具，避免回答下单后的过期库存。
- 使用 Streamlit 开发网页界面，侧边栏可视化 Agent 决策轨迹、RAG 命中片段与实时业务状态，支持多用户会话切换。
- 建立 22 条标准问答集自动评测（工具选择准确率、事实准确率、拒答正确率、幻觉拦截率），据评测结果修复 3 处 Prompt/检索缺陷，最终 22/22 通过；6 组回归测试共 76 项全部通过。
- 技术栈：Python 3.13 / DeepSeek API / OpenAI SDK / Function Calling / Prompt Engineering / RAG(TF-IDF) / Streamlit / JSON / 自动化测试。

## 版本 B：电商智能化 / 实习通用版（偏业务表达）

**AI 电商智能客服系统** ｜ 个人项目 ｜ 2026.09 – 2026.11

- 针对电商客服高频咨询（价格、库存、售后政策、物流、退款）场景，将关键词匹配程序升级为大模型驱动的智能客服，覆盖商品咨询、推荐、下单、订单跟踪与售后全流程。
- 梳理商品知识库与售后 FAQ 数据结构，设计订单/物流/退款/售后等**模拟**业务数据（明确标注非真实平台数据），实现下单扣库存、售后申请状态机与状态持久化，演示完整业务闭环。
- 通过工具调用 + 语义检索使回答严格依赖本地数据，对数据缺失场景统一返回「无法确认 + 引导人工」，避免大模型编造价格、库存与订单状态。
- 开发网页演示界面（含 Agent 决策轨迹与实时库存展示）、多轮对话与用户隔离，编写 22 条标准问答集完成自动评测（22/22 通过）与项目文档。

## 一页纸项目亮点（面试开场可用）

> 这是一个用大模型做「大脑」、用 Python 工具做「双手」的电商客服 Agent：
> 大脑理解意图并决定查什么，双手真正执行查询和办理业务，回答必须来自真实结果。
> 我最看重的四个工程点：RAG 的阈值拒答与父文档扩展、工具调用的异常兜底、
> 下单后强制重查的实时数据一致性、以及用标准评测集反向驱动 Prompt 优化。
